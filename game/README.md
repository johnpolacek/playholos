# Holos · the game

The v2 game shell, built from [the v2 mocks](../explorations/v2-mocks/index.html). Design is in [HOLOS_GAME_CONCEPT.md](../HOLOS_GAME_CONCEPT.md).

```bash
pnpm install --dir .. && pnpm install    # the atlas's packages, then the game's
pnpm dev                                 # http://localhost:5173
```

- A React app built with Vite, routed by React Router in `routes.tsx`, and served by one Cloudflare Worker. `worker/` answers `/api/*`, and every other address is the built client.
- `app/play/`: the shell. Top bar, map, tab page, and the rail. One route per tab.
  - It fills the screen at every size. Tall, as on a phone, the parts stack. Wide, from a phone on its side up, the map fills the left and the tab page and rail stand on the right. `wide:` in `app/globals.css` is that breakpoint: landscape, 640px and up.
  - Screens before the shell lay out with `components/spread.tsx`: one column when tall, capped to a readable width on a tablet, and the art beside the words when wide.
- `components/unlock.tsx`: the Mind is private in the test build. The rest of the game is open. On any production server, the Mind tab asks once for the code in `ACCESS_CODE` or the player's own Anthropic API key, and a cookie keeps it open. A key bills the player, and the Worker uses it per call without storing it. Only Console keys work: Anthropic's terms bar claude.ai logins in other apps. `worker/access.ts` holds the cookies. The dev server is open.
- `app/godview.tsx`: what the player can't see. Dev only.
- `worker/mind.ts`: the Mind's chat, on the AI SDK. Needs `ANTHROPIC_API_KEY` in `.dev.vars`.
  - `pnpm check:mind`, with the dev server going, asks the live Mind a few questions and checks its answers by code: that it knows its own Earth's road to Year 0 and speaks as we. A case that fails is asked once more, since the Mind words each answer anew: it reports a pass on a second try, and fails only twice running. It asks on your own Claude login through the `claude` CLI, or with `--via api` as players do, for a few cents.
  - `pnpm trace:mind`, with the dev server going, asks the live Mind every question in `evals/mind/cases.json`, each on a test Earth the file sets, and saves each answer beside what the Mind was told to `evals/mind/traces/`. It asks on your own Claude login through the `claude` CLI, at no API cost, with the same model, effort and prompt, though the CLI also tells it today's date and that it runs in the Claude Agent SDK. With `--via api` it asks as players do, about 4 cents a question. With `--dry`, it shows what each test Earth tells the Mind, for nothing. The dev server alone sends what the Mind was told. Of its hundred cases, twenty were written by hand, and eighty drawn as a test Earth, a kind of question and a style of asking, each question then written apart from the draw, by its own call on the login. Each answer is checked by code against the Mind's rules in `evals/mind/checks.mjs`: we not I, length, punctuation, plain names, odds in words, and never naming a model. A case marked `out`, where the Will grieves in their own life, may have the Mind step out and say I.
  - `pnpm review:mind` opens them at http://localhost:5190, one at a time, to mark pass or fail with a note, kept in `evals/mind/labels.json`. Reading them finds how the Mind fails before any check is written for it.
- Sending, from 2026-10-26: asked to send, the Mind ends its answer with a line `components/send-card.tsx` draws as a card, and Send keeps it in the save. `lib/sim/messages.ts` is the physics, from `calcs/messages.py`. A message lands without reply: the neighbors' replies were deleted on 2026-10-29. With `pnpm dev:cli`, the Mind answers on your own Claude login through `mind-cli.ts`. With Codex and no Claude Code, or `MIND_CLI=codex`, it answers on your ChatGPT login through the codex CLI, by way of `scripts/codex.mjs`. `pnpm trace:mind --via codex` traces it.
- `lib/game/`: the clock, save types, and the browser store.
- `lib/sim/`: the simulation, ported a piece at a time from Python in `../calcs/`. `pnpm test` checks it against Python.
  - `data/worlds/`: the pool of drawn worlds, one per seed, written by `python3 ../calcs/export_worlds.py`. They hold the seed's truth, so they ride inside the Worker, never among the public files. `worker/world.ts` reads them there, and `lib/sim/world.ts` from disk for the tests.
  - `knowledge.ts` is the wall: the Mind is told what Earth knows at that moment, never the truth.
  - `pyrandom.ts` is CPython's random generator, so a roll here matches the same roll in the calcs and the mocks.
  - `works.ts` paces Earth's works from the player's orders, in one loop from Year 0. `data/works.json` holds each work's Years and want.
  - `speeds.ts` is the one place a craft's travel time is worked out: ours by kind, and what another mind sends. Nothing else divides light-years by a speed. `calcs/speeds.py` holds what physics gives each trip.
  - `antimatter.ts` is what the Antimatter Works makes, on a hundredth of the swarm's power, growing as the swarm does. `speeds.ts` has its drive's trips, and `lib/game/reach.ts`'s `amQueue` sends a craft by it only if that lands it soonest. `calcs/antimatter.py` holds the sources.
  - Our bullets were retired 2026-11-13, with `strikes.ts`, `reprisals.ts`, `meetings.ts` and `calcs/strikes.py`: git history holds them. `conflict.ts` keeps a bullet's harm, the measure the watcher's maker strikes with.
  - `ladder.ts` is what the watcher's maker does once we spread: warn, contain, strike. Since 2026-11-13 it also plays our one weapon, wrecking the watcher with the Interceptor's kill vehicle (`components/wreck-card.tsx`, on the watcher's page): `answerToWreck` has its maker contain us if hostile, or send another watcher.

- `lib/drift.ts`: the game's one scene, in Three.js with the atlas's ephemeris, stars and galaxies from `../src`, `../assets` and `../data`. Today's Earth with its night lights, the planets, the HYG stars, and a Milky Way drawn to its measured arms. It draws four scales, each in its own units, far to near, so no float spans Earth to Andromeda. Sources in HOLOS_RESEARCH.md, The drift.
  - Light in the drawing, 2026-11-09, chosen from `../explorations/graphics/`: the layers draw to one half-float buffer, bloom spreads what is brighter than white, and a last pass rolls the brightest light off, darkens the corners a little and lays a faint grain over it (still under reduced motion). A glow's `uGain` lifts it past white where it should flare: the Sun, the city lamps, a knock's front, a bright star. Earth wears a slate sea under its dots, thin cloud, and air that scatters blue where the Sun is up and gold toward it. The Moon and the planets carry their maps faint under their dots. Scan's and Where things stand's maps lie on a plane lit from Sol, the far side past Sol fades, and light runs out along each thread. Multisampling is on only at 1x, since resolving the half-float buffer at 2x cost 60 fps down to 25. `?flat` on any address draws straight to the screen as before.
  - The Universe tour's stops carry light too, 2026-11-10: on Our nearest stars, light leaves Sol along every line at once and lands on each star in turn, at a second and a half a light-year, and the star flares; Our Sun, today stands back to one light-day, a ring at 173.14 AU with Voyager 1 drawn at its distance for the date; Our corner of it has faint motes falling toward the Great Attractor; Our Local Group marks each galaxy with a soft point sized by its size. `lib/sim/tour.ts` holds the stops' words and notes.
  - `lib/sim/flight-view.ts`, the simulation's own flight on `/sim`, carries the same light since 2026-11-10: its own composer with bloom and the finish pass, the bodies' cores past white, and a running light along the thread from Sol that reaches the place in view in two and a half seconds and flares it. While the flight has the screen, the sky under it rests (`sim.rest`) and draws nothing, so the two never share a frame.
  - The sections, settled 2026-11-10: `/universe` is the tour and two flights through the real, Stars (the twelve nearest) and Worlds (every known planet within 50 light-years, `data/planets-50ly.json` from `../calcs/export_planets.py`); `/sim` is two flights through what the dials draw, Minds and Peers. The drawn warm worlds are no longer flown or drawn: the Worker still draws them for the sim's words, and nothing shows them.
  - `lib/flight.ts` places its camera: one director for the title's loop, every screen's view and the map, easing distance, turn and tilt between them, so the camera zooms, pans and orbits from one view to the next and never cuts. The map rests at five stops, flies between them, and turns with a drag.
  - Three.js and Astronomy Engine come from the atlas's packages at the repo root. The game keeps only Three.js's types.
- `components/sky.tsx`: the game's one sky, behind every screen from the title to the charter and on into the shell, where the map strip is its window. Each screen's `SkyArt` is an empty box in its layout where the sky frames the screen's subject, with the screen's dials: the sunrise on Wake, the Sun's road on Where we come from (timed by `lib/game/road.ts`), the lights and threads on Who they are, the radar shell on Where things stand, the flight out to Voyager 1 on What you inherit, and Earth and the Moon behind the charter. Each screen's story waits for the camera to arrive.
- `components/drift.tsx`: a new game's first screen, before Wake. No title: the slow loop from Earth out to the Local Group and home, and Begin game, which dives home to Earth.
- `components/map-strip.tsx`: the map strip, the sky's window in the shell. The camera flies in from the charter, and back out to the title on New game.
- `components/menu.tsx`: the galactic year in the top bar's corner, Sol circling the galaxy's glowing, breathing core. It opens a drawer: the player's Anthropic key, New game, the about pages, and links out.

- The game is always dark: the colors in `app/globals.css`, and `lib/ink.ts` for the memory screens' canvases. Screens before the shell open with `components/screen-bar.tsx`, by way of `Spread`: the real record on the left.
- `lib/motion.ts`: the full motion treatment, from the animaxxing skills, whose sources are in `../skills-lock.json`. Every element enters from a blank screen, rests, and leaves. Mark an element `data-m` and give its screen a `useStage` intro. Reduced motion skips the travel.

Everything else inside the shell is placeholder.

## Shared UI

Every piece two screens or more share. The kit's own parts on ui-sdk sit in `components/kit/`. Use these before writing a new one, and add a part here and to `/design` when a second screen needs it. `/design` draws them all live, with the colors and type, from `app/design.tsx`. `/ui` draws each on its own numbered card, laid out as SPEC-01/HARDWARE lays out its own, from `app/ui.tsx`. The two share one bar, `app/kit-layout.tsx`. `/ui`'s views, in `app/views/` and laid out as SPEC-01's own (`View` in `app/views/frame.tsx`), are the game's screens drawn by the same parts the game draws them with, fed a fixed Earth: a screen splits into a part that draws it and the game's part that feeds it, as `TopBar` and `Hud` do. Add a view to `VIEWS` and to `routes.tsx`.

Skins, since 2026-11-15. A skin is a `data-skin` attribute on the page's root, set by `lib/skin.ts`. `chalk` is the game as it has been, and the default. `instrument` draws the game as a console, after SPEC-01/HARDWARE but dark and sober: matte panels, labels cut into them, lamps, knobs, a real switch, the map behind glass, and the Mind's notes on a teleprinter's tape. It is a design exploration and never the default. Its colors and surfaces (`hw-panel`, `hw-well`, `hw-key`, `hw-key-dark`, `engrave`, `hw-glass`, `hw-tape`) sit under the attribute in `app/globals.css` and do nothing in chalk. A kit part names a class for it with the `instrument:` variant, and reads `useSkin()` only where its markup differs: Range's knob, Choice's switch, the Meter's lamps. `log`, since 2026-11-15, draws the game as an observatory's logbook: dark ruled paper with faint ledger lines, Newsreader for the record and IBM Plex Mono for the data at the game's own sizes, a reading as a dated entry, the Mind's notes in the margin in italic, and buttons as stamped labels. It is an exploration too, and never the default. It styles the same names Instrument does in its own way (`hw-panel` is ruled paper, `hw-key` a squared label, `engrave` mono, `hw-tape` the margin's hand), and adds three of its own: `ledger` rules a paper that is no panel, as a tab's page; `stamp` gives a button 28px tall or more the second rule inside its edge; `graduated` makes a Meter's track a ticked scale. A part names a class for it with the `log:` variant. The dots in the `/ui` bar pick the skin for every card and view, kept per viewer. `?skin=instrument` or `?skin=log` on any address plays the game in it until the next full load, for playtests. A new part gets its Instrument and Log looks with it, and any new motion its reduced form.

Live at https://playholos.com, on the Cloudflare Worker `holos`. `pnpm run deploy` builds the client and the Worker and deploys both. Nothing deploys on push. The `deploy` workflow in `.github/workflows/deploy.yml` does the same on GitHub when started by hand, with the `CLOUDFLARE_API_TOKEN` repository secret: a cloud session can't run wrangler's asset upload through its proxy, so it deploys this way. The Worker's secrets, `ANTHROPIC_API_KEY` and `ACCESS_CODE`, are set with `pnpm exec wrangler secret put` and never committed. Locally they go in `.dev.vars`. Players without a key can open the Mind on us: they pass a Cloudflare Turnstile check, get a pass for a week, and may ask 100 questions a day on Sonnet, while all passes together spend at most $7 a day (`worker/allowance.ts`). Passes need `TURNSTILE_SITE_KEY` in `wrangler.jsonc` and the `TURNSTILE_SECRET` secret. Without them, no passes are offered. `pnpm events` shows how people play, from the anonymous events `lib/track.ts` sends from playholos.com only. It needs `CLOUDFLARE_API_TOKEN` in `.dev.vars`, with Account Analytics read. The card a shared link shows and the home screen icon are drawn as the client is built, from `app/card.tsx` and `app/apple-icon.tsx`.

## Orders in the save, proposed

Not wired yet. Agree this with the UI before either side builds on it.

- `Save` gains `orders?: Order[]`, with `Order` from `lib/sim/works.ts`.
- An order is stamped with the game Year it was given: `yearAt(beganAt)` at the tap, 0 while planning before Begin.
- The list only grows. A change of mind is a new order, never an edit.
- Four kinds so far:
  - `{ y, begin: "Moon vault" }`: a work joins the end of the line. `"Data center"` queues one for the fabs.
  - `{ y, first: "Moon vault" }`: the player moves a work under way to the front.
  - `{ y, standing: "Data center" }`: the fabs keep data centers coming.
  - `{ y, studies: 0.1 }`: thought set aside for the Mind's studies.
- Work names are the keys of `data/works.json`.
- The chat request sends `orders` with `seed` and `beganAt`. The server replays them all with `pace(orders, now, { scale: world.earth.compute })`, so a date never drifts.
